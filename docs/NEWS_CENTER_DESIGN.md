# BongoStock 资讯中心设计与实施计划

## 1. 目标

在现有行情浮窗中增加“行情 / 资讯”双模式入口，让用户可以在不离开桌宠浮窗的情况下：

- 查看全市场新闻、早午晚简报和个股新闻。
- 使用内置检索词，也可以输入完整的自定义检索词。
- 客户端不提供时间或排序控件，固定请求“不限”并按发布时间倒序展示；Gateway 协议仍保留其他时间范围和排序能力。
- 从 BongoStock 本地自选分组中选择个股并检索新闻。

资讯数据暂时只使用东方财富妙想 `news-search`，不接入东方财富自选股管理 Skill。

## 2. 已确认的接口边界

### 2.1 妙想公开请求格式

目前公开 Skill 只发送：

```json
{
  "query": "检索词"
}
```

没有公开且可用的以下参数：

- 精确起始时间和结束时间。
- 返回数量。
- 排序字段和排序方向。

显式附加 `startDate`、`endDate`、`size` 会被当前接口忽略。

### 2.2 时间范围

Gateway 协议保留时间范围能力，供接口完整性和未来扩展使用：

1. 将“最近1日 / 3日 / 7日”等描述写进检索词，改善语义召回。
2. 根据返回的 `publishDate` 严格过滤；没有 `publishDate` 时使用 `date`。

时间定义：

- 1日：最近24小时。
- 3日：最近72小时。
- 7日：最近168小时。
- 不限：Gateway 不执行时间过滤。

当前 BongoStock 客户端固定发送“不限”，不显示时间范围控件，并固定使用“最新”排序。

### 2.3 排序

只保留三种排序：

- **默认**：保持妙想返回顺序。
- **最新**：按有效发布时间倒序。
- **最旧**：按有效发布时间正序。

“默认”是唯一来自妙想接口的原生顺序。妙想没有公开的排序参数；“最新”和“最旧”均由 Gateway 执行，客户端只显示处理后的结果。

不实现自定义“综合排序”，不使用不稳定的 `rankScore` 重新打分。

当扩展检索包含两次不同调用时，默认排序采用交替合并：A1、B1、A2、B2……，并在合并过程中去重，以尽量保留两组结果各自的原始次序。

### 2.4 结果数量

界面不承诺精确召回数量，使用“结果档位”：

- **10条**：调用一次，以十条左右的结果集为目标，不承诺精确条数。
- **20条**：允许两次互补查询，合并去重后展示约二十条结果。

相同检索词不会重复调用两次。扩展模式必须生成语义互补的查询，例如：

| 场景 | 查询 A | 查询 B |
|---|---|---|
| 全市场 | 市场行情、宏观政策 | 行业动态、公司新闻、公告 |
| 简报 | 市场综述、重要事件 | 政策、行业、公司动态 |
| 个股 | 个股新闻、公司公告 | 研报、机构观点、行业影响 |

合并去重后不足目标数量时，显示实际数量，不重复调用相同检索词强行补足。

## 3. 系统架构与服务器配置

资讯请求必须通过用户配置的 BongoStock Gateway 转发，客户端不直接请求东方财富妙想：

```text
BongoStock 客户端
  └─ HTTPS + Bearer Token
      └─ BongoStock Gateway
          └─ HTTPS + MX_APIKEY
              └─ mkapi2.dfcfs.com/news-search
```

资讯服务与行情数据源选择相互独立。即使客户端行情选择“内置行情”，只要已经配置 Gateway 地址和 Bearer Token，资讯中心仍然可以使用 Gateway。客户端复用现有外接服务的地址、Token 和超时配置，不保存妙想 API Key。

资讯能力完全服务端化：

- 客户端不内置资讯 Provider。
- 客户端不直连妙想，也不保存妙想域名或 API Key。
- 客户端不提供本地资讯源或本地回退。
- Gateway 不可用或未配置资讯时，只显示“资讯服务不可用”。
- 检索词生成、扩展检索、时间过滤、排序、类型过滤、去重和缓存全部由 Gateway 完成。
- 客户端只负责提交选项、渲染结果和保存已读状态。

Gateway 需要增加：

- `POST /v1/news/search` 资讯转发接口。
- `GET /v1/capabilities` 中的 `news` 能力声明。
- 妙想响应规范化、互补检索、去重、缓存、超时和错误映射。
- 独立的新闻请求缓存，默认5分钟。
- 只记录请求方法、路径、状态和耗时，不记录检索词、正文、Bearer Token 或妙想 API Key。

建议的能力声明：

```json
{
  "protocol": "bongostock-market-v1",
  "news": {
    "enabled": true,
    "provider": "mx-news-search",
    "sorts": ["default", "newest", "oldest"],
    "depths": ["compact", "standard", "extended"]
  }
}
```

当前客户端请求示例：

```json
{
  "scope": "market",
  "preset": "overview",
  "timeRange": "all",
  "sort": "newest",
  "depth": "extended",
  "types": ["news", "announcement", "report", "external"]
}
```

- 客户端可额外传入一次性的 `query`，个股范围还会传入 `security`；默认查询和扩展模式的互补查询由 Gateway 根据范围与预设生成。
- 标准模式调用一次上游；扩展模式最多生成两个互补查询。
- Gateway 拒绝空查询、超长查询和超过两个查询的请求。
- Gateway 返回已经完成时间过滤、排序、类型过滤和去重的规范化结果，以及原始条数、超期条数、重复条数和抓取时间。

Gateway 服务端环境文件 `/etc/bongostock-gateway.env` 需要增加：

```dotenv
# 妙想 API Key；不配置时 capabilities.news.enabled=false
MX_APIKEY=replace-with-a-new-key

# 可选配置
BONGOSTOCK_NEWS_TIMEOUT_MS=15000
BONGOSTOCK_NEWS_CACHE_MS=300000
```

配置要求：

- 环境文件权限保持 `600`，不得提交真实环境文件。
- 服务器需要能够通过 HTTPS 访问 `mkapi2.dfcfs.com:443`。
- 不需要新增公网入站端口，继续通过现有 Nginx 443 和 Gateway 8787 转发。
- 客户端只访问 Gateway，因此不需要把妙想域名加入客户端 CSP，也不保留任何本地资讯访问能力。
- `MX_APIKEY` 缺失时行情功能继续正常工作，资讯入口显示“资讯服务未配置”。
- 部署前必须重置当前测试 Key，再把新 Key 写入服务器环境文件并重启服务。

1. 更新客户端 README、功能基线、部署说明、网络请求说明和项目接续文档。
2. 执行发布审计，确认客户端和仓库中没有妙想 API Key、直连地址或本地资讯 Provider。
3. 单独提交并推送 BongoStock 客户端代码和文档。
4. 关闭旧客户端，构建 release 并替换本机运行版本。
5. 启动最新版并完成最终桌面冒烟测试。

## 10. 验收标准

- 顶部显示“行情 / 资讯”，默认打开行情。
- 行情窗口不加宽，原有股票卡片和猫咪位置不发生错位。
- 资讯模式保持紧凑、小字且无可见滚动条。
- 客户端不显示时间筛选或排序控件，固定不限时间并按时间倒序。
- 标准检索只调用一次；扩展检索最多调用两次且不重复发送相同查询。
- 个股资讯能够联动 BongoStock 本地分组、股票、指数和基金。
- API Key 不出现在客户端、仓库或日志中。
- 客户端不存在本地资讯源、妙想直连或资讯回退能力。
- Windows 和 macOS 均能正确拖动、关闭、置顶、变淡和重新定位浮窗。
